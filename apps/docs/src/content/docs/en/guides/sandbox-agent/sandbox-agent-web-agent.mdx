title: Build a Coding Agent with Sandbox Agent SDK on Daytona
description: Run Sandbox Agent inside Daytona and control it from a local TypeScript app.

This guide runs [Sandbox Agent](https://github.com/rivet-dev/sandbox-agent) inside Daytona, then connects from local TypeScript using the [Sandbox Agent SDK](https://sandboxagent.dev/docs/sdk-overview) (npm: [`sandbox-agent`](https://www.npmjs.com/package/sandbox-agent)).

Running coding agents remotely is hard: local-first SDK assumptions, fragile SSH streaming/TTY behavior, and incompatible agent APIs. Sandbox Agent SDK gives you one integration surface for session lifecycle, prompts, and streaming events across agents.

Sandbox sessions are ephemeral by default. If you need replay/audit, use [session persistence](https://sandboxagent.dev/docs/session-persistence).

## 1. What this script does

When you run it, the script:

1. Automatically prepares a shared Daytona snapshot.
2. Creates a sandbox from that snapshot.
3. Starts `sandbox-agent server` on port `3000`.
4. Creates a session and prints an Inspector URL.

The snapshot name is `sandbox-agent-ready` and includes `sandbox-agent`, `claude`, and `codex`. First run builds it once and can take a few minutes. Next runs reuse it automatically.

## 2. Prerequisites

- Node.js 18+
- `DAYTONA_API_KEY`
- At least one provider key:
  - `OPENAI_API_KEY` or `CODEX_API_KEY` (for `codex`)
  - `ANTHROPIC_API_KEY` (for `claude`)
- Additional agent credentials: [Sandbox Agent credential docs](https://sandboxagent.dev/docs/credentials)

## 3. Project setup

Clone Daytona and open this guide project:

```bash
git clone https://github.com/daytonaio/daytona.git
cd daytona/guides/typescript/sandbox-agent/sandbox-agent-web-agent
```

Create `.env`:

```bash
DAYTONA_API_KEY=your_daytona_key
OPENAI_API_KEY=your_openai_key
# Optional
# CODEX_API_KEY=your_codex_key
# ANTHROPIC_API_KEY=your_anthropic_key
```

Install and run:

```bash
npm install
npm run start
```

To keep the sandbox alive while you inspect the session:

```bash
KEEP_ALIVE=1 npm run start
```

## 4. Main script flow

### Start the server

The script starts Sandbox Agent in the Daytona sandbox:

```ts
await run(
  `nohup sandbox-agent --no-token server --host 0.0.0.0 --port ${SERVER_PORT} >/tmp/sandbox-agent.log 2>&1 &`,
)
```

### Create session

After health check succeeds, it connects and creates a session:

```ts
const sdk = await SandboxAgent.connect({ baseUrl })
const session = await sdk.createSession({ agent })
```

`agent` resolves to `claude` if `ANTHROPIC_API_KEY` is set, otherwise `codex`.

### Send message + stream events

The example keeps this section commented by default so startup remains minimal. Uncomment it in `src/index.ts` to run one prompt and stream events:

```ts
// const off = session.onEvent((event) => {
//   console.log(`[event] ${event.type}`)
// })
// await session.prompt([{ type: 'text', text: 'Reply with exactly: sandbox-agent-ready' }])
// off()
```

### Get response in Inspector

The script prints:

```txt
Inspector UI: https://.../ui/sessions/<session-id>
```

By default, the script deletes the sandbox after setup. Use `KEEP_ALIVE=1` to keep it running while you inspect the URL.
