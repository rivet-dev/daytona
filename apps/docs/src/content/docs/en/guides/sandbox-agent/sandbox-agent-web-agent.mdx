This guide shows how to run a [Sandbox Agent](https://github.com/rivet-dev/sandbox-agent) server inside a Daytona sandbox and connect to it using the Sandbox Agent TypeScript SDK.

Running coding agents remotely is hard. Existing SDKs assume local execution, SSH-based approaches break streaming and interactive workflows, and each coding agent exposes a different API.

Building this from scratch usually means reimplementing transport, session lifecycle, and event handling for every agent.

Sandbox Agent solves three problems:

- **Coding agents need sandboxes:** you should not let AI run arbitrary code on production hosts. Sandbox Agent runs inside an isolated Daytona sandbox and exposes HTTP/SSE for remote control.
- **Every coding agent is different:** Claude Code, Codex, OpenCode, Cursor, Amp, and Pi have different APIs and behaviors. Sandbox Agent provides one API, so swapping agents is a config change, not a rewrite.
- **Sessions are ephemeral:** raw agent transcripts usually disappear with sandbox/process lifecycle. Sandbox Agent emits a universal event schema you can store, replay, and audit in your own systems.

In this Daytona guide, Daytona hosts the Sandbox Agent server and your local TypeScript app connects with `sandbox-agent` SDK to control sessions and stream events.

---

### 1. Workflow Overview

When you run the script, it creates a Daytona sandbox, installs Sandbox Agent CLI inside that sandbox, installs your selected coding agent, and starts `sandbox-agent server`.

Your local TypeScript script then connects to that remote server using `SandboxAgent.connect(...)`, creates a session, and prints the Inspector URL:

```bash
$ npm run start
Creating sandbox...
Installing Sandbox Agent CLI...
Installing agent (codex)...
Starting Sandbox Agent server...
Waiting for server health...
Inspector UI: https://3000-xxxxxxxx.proxy.daytona.works/ui/?token=...&sessionId=...
Session is ready. Press Ctrl+C to delete sandbox and exit.
```

### 2. Project Setup

#### Clone the Repository

Clone Daytona and open this guide project:

```bash
git clone https://github.com/daytonaio/daytona.git
cd daytona/guides/typescript/sandbox-agent/sandbox-agent-web-agent
```

#### Configure Environment

Get your Daytona API key from [Daytona Dashboard](https://app.daytona.io/dashboard/keys).

You also need at least one model provider key:

- `OPENAI_API_KEY` or `CODEX_API_KEY` for `codex`
- `ANTHROPIC_API_KEY` for `claude`
- Other agents may require additional credentials. Set any extra provider keys as environment variables so they are available inside the sandbox.

Copy `.env.example` to `.env`:

```bash
DAYTONA_API_KEY=your_daytona_key
OPENAI_API_KEY=your_openai_key
# Optional
# CODEX_API_KEY=your_codex_key
# ANTHROPIC_API_KEY=your_anthropic_key
# AGENT=codex
```

:::caution[API Key Security]
Provider keys are passed into the Daytona sandbox environment and may be accessible to code executed inside that sandbox.
:::

#### Local Usage

:::note[Node.js Version]
Node.js 18 or newer is required.
:::

Install and run:

```bash
npm install
npm run start
```

### 3. Understanding the Script

This example keeps the setup intentionally simple: it installs Sandbox Agent at runtime instead of using snapshots.

#### Initialization

On startup, the script:

1. Creates a Daytona sandbox.
2. Installs `@sandbox-agent/cli@0.2.x` inside the sandbox.
3. Installs the selected agent.
4. Starts `sandbox-agent server` on port `3000`.
5. Waits for `/v1/health`, connects via `SandboxAgent.connect`, and creates a session.

#### Main Script Code

The script runs all sandbox commands through a checked helper so failures are explicit:

```typescript
const runChecked = async (command: string) => {
  const result = await sandbox.process.executeCommand(command)
  if (result.exitCode !== 0) {
    throw new Error(`Command failed (${result.exitCode}): ${command}\n${result.result || ''}`.trim())
  }
}
```

After the server is healthy, the local SDK connects and creates a session:

```typescript
const sdk = await SandboxAgent.connect({ baseUrl, token: SERVER_TOKEN })
const session = await sdk.createSession({ agent })
```

If `AGENT` is set, that agent is used. Otherwise the script defaults to `codex` when OpenAI/Codex keys exist, or `claude` when Anthropic key exists.

#### Clean up

Press `Ctrl+C` to delete the sandbox and stop the script.

### Features

- **Universal Agent API**

Claude Code, Codex, OpenCode, and Amp each have different APIs. Sandbox Agent exposes one HTTP API that works across all of them.

- **Streaming Events**

Real-time SSE stream of everything the agent does. Persist to your storage, replay sessions, audit everything.

- **Universal Schema**

Standardized session schema that covers all features of all agents. Includes tool calls, permission requests, file edits, etc.

- **Runs Inside Any Sandbox**

Run Sandbox Agent inside E2B, Daytona, Vercel Sandboxes, or Docker.

- **Full Session Lifecycle Management**

Create sessions, send messages, persist transcripts. Full session lifecycle management over HTTP.

- **OpenCode Support**

Experimental.

Connect OpenCode CLI, SDK, or web UI to control agents through familiar OpenCode tooling.
